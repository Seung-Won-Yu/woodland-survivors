# 레퍼런스 시스템 분석 0.8 · 이전 조사 기록

> **2026-11-05 업데이트:** 사용자 제공 PDF/이미지를 직접 읽은 [0.9 자료 분석](REFERENCE-ANALYSIS-V09.md)이 이 문서의 현행 기준을 대체합니다. 아래는 당시 원격 공식 자료만으로 확인했던 범위의 기록이며, 현재 개발 규칙은 [게임 기획](GAME-DESIGN.md)을 따릅니다.

2026-11-04 · 공개 규칙의 설계 역분석 · 실행 파일 분석이나 원작 코드·자산 복제가 아님

현재 주 레퍼런스는 **MegaBonk / ClessioTV의 Pokémon Survivor Burst**다. PokéRogue, JPTER78의 브라우저 PokéSurvivor는 다른 게임이다. 기존 [0.7 조사](BENCHMARK-V07.md)의 PokéRogue 분석은 보조 연구로 보존하며, Burst를 분석한 자료로 취급하지 않는다. 개발 방향은 [게임 기획](GAME-DESIGN.md), 캐릭터 규칙은 [대원 설계](CHARACTER-DESIGN.md)를 따른다.

## 1. 무엇을 역설계하는가

게임을 다음 여섯 층으로 분해한다. 화면 모양·기능 목록보다 **입력 → 자원 → 선택 → 능력 변화 → 새 과제**의 관계를 분석한다.

| 층 | 확인할 질문 | 우리 게임의 산출물 |
| --- | --- | --- |
| 출전 설정 | 캐릭터·시작 장비·난도가 어떤 플레이를 약속하는가? | 역할·성장 조건·추천 조합·약점이 보이는 대원 선택 |
| 캐릭터 성장 | 어떤 행동/자원이 그 캐릭터를 더 강하게 하는가? | 대원별 숙련 규칙·분기·고유기 |
| 장비 성장 | 전용 무기 강화와 공통 스탯은 어떻게 다른가? | 무기별 성장 축, 보조 장비의 범위, 슬롯 비용 |
| 완성 보상 | 진화·결합이 무엇을 소비하고 무엇을 돌려주는가? | 재료 투자·진화 인장·최종 합체·슬롯 회수 |

| 재도전 | 실패/완주 뒤 무엇이 남고 무엇을 새로 선택하는가? | 대원별 도전·발견·기록, 다음 run 초기화 범위 |

## 2. MegaBonk: 캐릭터별로 ‘좋은 선택’이 달라지는 구조

### 확인 사실

공식 소개는 처치·XP 회수·무작위 희귀도 업그레이드·아이템 시너지를 하나의 성장 회로로 설명한다. 공식 도전 과제는 스테이지 완료, 빠른 보스 처치, 특정 무기/행동 사용 등으로 나뉜다. [개발사 소개](https://store.steampowered.com/app/3405340/Megabonk/), [공식 도전 과제](https://steamcommunity.com/achievements/3405340)

개발자의 2025-10-19 패치에서는 이동 속도에 연동되는 Calcium, 금화에 연동되는 Robinette, 고유 행동에 연동되는 Megachad, 동결된 적과 연동되는 Noelle을 서로 다른 성장 사례로 확인할 수 있다. 이는 당시 패치의 사례이며 현재의 정확한 수치를 복제하는 표가 아니다. [개발자 패치 원문](https://store.steampowered.com/news/posts/?enddate=1760905221&feed=steam_community_announcements)

### 인과 구조에서 도출한 설계

| 성장 유형 | 성장 원천 → 보상 | 달라지는 플레이 판단 | Woodland에서 시험할 유형 |
| --- | --- | --- | --- |
| 기동 환산 | 이동/속도 → 공격의 효율 | 안전한 원을 그릴지, 보상을 회수하러 갈지 | 토끼의 전투 이동·왕복 공격 |
| 경제 환산 | 재화 확보 → 전투력 | 당장 안전과 수집 투자 사이의 선택 | 수달의 실제 회수와 순환 |
| 행동 누적 | 고유 행동 → 판 안의 성장 | 고유기를 언제, 어떤 무리에 쓸지 | 고슴도치의 방어·반격 |
| 상태 이용 | 적에게 만든 상태 → 추가 화력 | 상태를 만드는 공격과 소비하는 공격의 조합 | 두더지의 지대·끌어모으기 |
| 표적 전문화 | 특정 표적에 집중 → 다음 사냥 강화 | 잡몹 학살과 정예 추적의 우선순위 | 여우의 표식 사냥 |

오른쪽은 우리의 설계안이다. 원작 캐릭터에 같은 규칙이 모두 존재한다고 주장하지 않는다. 중요한 원리는 캐릭터 선택이 이후의 **무기 선택, 이동, 보상 우선순위**를 바꾼다는 점이다.

### 무기·공통 강화·발동 아이템을 분리한다

개발자 패치에는 무기별 유효 스탯 안내, 무기와 Tome의 상한 확장 구분, 발동 계수, 과도한 지속시간이 투사체 한도를 점유하던 수정이 있다. [Steam 공식 패치 API](https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid=3405340&count=100&maxlength=0): v1.0.12(2025-10-08), Christmas(2025-12-25), H A T S(2026-01-25).

우리 적용 원칙:

1. 무기는 자기 공격 문법을 바꾼다. 산탄·왕복·궤도·추적·장판을 모두 같은 피해 +N으로 취급하지 않는다.
2. 보조 장비는 명시한 공통 축을 강화한다. 적용되지 않는 스탯은 추천하지 않는다.
3. 유물은 조건부 추가 효과다. 유물 발동이 새 유물 발동을 무한히 생성하지 않게 한다.
4. ‘많은 적’과 ‘더 많은 XP’는 같은 말이 아니다. 대공세의 처치 쾌감과 성장 예산을 따로 설계한다.
5. 과도한 이펙트와 투사체가 기본 공격·경고를 가리는 것은 성장의 보상으로 취급하지 않는다.

**미확인:** MegaBonk의 정확한 현행 전체 상수, 모든 캐릭터/아이템 공식, 공식 weapon fusion 시스템. 미확인 사항을 게임 설정의 사실로 채워 넣지 않는다.

## 3. Pokémon Survivor Burst: 캐릭터 선택 → 성장·진화 → 큰 고유 행동

### 확인 사실

Clessio의 공식 배포 페이지는 run 중 레벨업·진화, 패시브·복수 공격·Burst 공격·시너지를 명시하고, 특정 대원의 run 도전으로 다른 플레이 가능 대원을 여는 구조와 최고 기록 경쟁을 설명한다. 이는 PokéRogue의 DNA 합성이나 브라우저 PokéSurvivor의 수집 체계를 설명하는 자료가 아니다. [공식 배포 페이지](https://clessio.itch.io/pokmon-survivor-burst), 2026-11-02 갱신 확인.

개발자 출시 스레드에서는 Classic/Rush/Tower라는 별도 모드와 당시 대원별 해금 사슬을 확인했고, 과거 업데이트에는 별도 Endless와 전용 상점/통화도 설명된다. 모드별 숫자·해금 사슬은 버전 변경 가능성이 있어 현재 불변 규칙으로 복사하지 않는다. [당시 개발자 해금 설명](https://eeveeexpo.com/threads/9705/post-93792), [4.5 변경 기록](https://eeveeexpo.com/threads/9705/post-93830)

### 우리에게 옮길 관계

| 원작에서 확인한 관계 | 가져올 원리 | 가져오지 않을 규모 |
| --- | --- | --- |
| 한 캐릭터도 공격·패시브 선택으로 여러 build를 만들 수 있음 | 대원별 추천이 정답 강제가 되지 않게 분기 제공 | 수십 대원·많은 기술의 즉시 추가 |
| run 중 진화와 Burst가 존재 | 작은 강화·중간 변화·큰 폭발을 다른 사건으로 만들기 | Pokémon 종·타입·원작 연출 |
| 특정 대원의 challenge → 새 선택권 | 대원별 숙련 과제를 재도전 목표로 사용 | 가챠·배틀패스·방대한 재화 |
| 모드와 해금 경로를 구분 | 핵심 원정과 이후 기록 도전의 규칙을 명확히 구분 | 원정/Rush/Tower/Endless 동시 개발 |

우리의 무기 최종 합체는 별도 설계다. Burst가 무기 두 개를 반드시 합쳐 주는 게임이라고 단정하지 않는다. 합체의 재료 소모·슬롯 회수·공격 변화는 [공식 Vampire Survivors Evolution 설명](https://vampire.survivors.wiki/w/Evolution)을 보조 패턴으로 검토했다.

## 4. 현재 실험이 보여 준 것과 보여 주지 못한 것

현재 0.7 미배포 작업본은 16회 일반 입력 모델에서 첫 돌파·두 합체 경로·일부 3단계 유지를 재현했다. 전원 종료 HP는 100이지만, 30초 표본의 최저 HP는 65이고 누적 피해도 있었다. 따라서 ‘전혀 위험이 없다’고 단정할 근거는 아니다.

반대로 이는 선택의 재미를 입증하지 않는다. 같은 점수표의 주행 정책이 회피·회복·고유기를 반복 사용한다. 최종 무기 세트의 수렴, 무기 1→8의 무료 도약, 무제한 추가 XP와 고유기 충전이 빌드 차이를 희석할 가능성이 있다. 다음 검증은 생존율 외에 **무슨 선택을 포기했는지, 어떤 행동으로 성장했는지, 두 빌드가 어디서 각각 유리한지**를 비교해야 한다.

측정물: `outputs/v07-final-model.json`, `outputs/v07-union-before.json`, `outputs/v07-union-after.json`. 전체 주행과 고정 전투 비교는 별개이며 이 파일들은 배포물에 포함하지 않는다.

## 5. 문서의 한계

보내주신 [나무위키 Megabonk](https://namu.wiki/w/Megabonk)는 도구 접근 정책으로 열람하지 못했다. 해당 표를 읽거나 검증했다고 주장하지 않는다. 위 분석은 직접 확인한 개발자 자료에 기반한다. 원작 장기 플레이·유저 잔존율 실험·현재 모든 밸런스 수치의 복원까지 수행한 분석도 아니다.

결정은 원리를 따른다. **캐릭터별로 성장 원천이 달라야 하고, 장비 선택이 그 원천을 증폭하거나 다른 약점을 보완해야 하며, 보스가 그 선택을 시험해야 한다.** 아래 두 기획 문서가 이를 우리 게임의 규칙으로 바꾼다.
