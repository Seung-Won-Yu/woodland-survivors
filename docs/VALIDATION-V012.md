# 0.12 — 첫 작전과 기지 순환

검증일: 2026-11-05. 규칙 `operation-0.12.0`.

## 구현 범위

- 루트 화면을 작전실로 교체. 작전실·병영·무기고·훈련장, 대원별 교범과 기록.
- 마르코 P 집중, 피오 H 강화 탄창. P/H/R 숙련 3단계·핵심 진화·H+R 최종 합체.
- 포로 5명, 두 거점, 탄약 수송대, 선택 Slug, 부위 파괴가 있는 지휘전차.
- 처치·구출·거점·부위·완주 정산, 최초 보고/완주 보너스, 영구 연구·상한 훈련·훈련 실지불 환불.
- 첫 완주로 과밀 난이도 해금. 캐릭터·난이도·규칙별 최고 기록.
- 한 판 snapshot, 체크포인트, 중복 정산 차단, 저장 실패 재시도, 손상된 작전의 성과 복구 정산.
- 군사 픽셀 아트와 새 UI. 기존 게임은 `woodland.html`, `prototype.html`에 보존.

기획의 다음 지역·나머지 대원은 이번 구현에 포함하지 않았다. [전체 기획](METAL-SLUG-SURVIVORS-CONCEPT.md)과 [경제 계약](META-PROGRESSION-ECONOMY.md)을 참고한다.

## 입력 주행

`node scripts/mission-pilot.mjs --summary`로 재현한다. 초기 계정, 연구/훈련 없음, seeds 17·71, 두 대원 × 도보/Slug의 8회다. HP·무장·시간을 주입하지 않고 선택·이동·회피·전술기·상호작용 API를 사용한다. 정책은 모델 상태로 경로와 위험을 정확히 판단하므로 사람보다 유리하다.

| 대원 | Slug | 완주 | 중앙 완료 | 중앙 보스 전투 | 중앙 처치 |
|---|---|---|---|---|---|
| 마르코 | 없음 | 2/2 | 101.1초 | 21.6초 | 566 |
| 마르코 | 탑승 | 2/2 | 120.7초 | 19.2초 | 828 |
| 피오 | 없음 | 2/2 | 74.8초 | 12.6초 | 412.5 |
| 피오 | 탑승 | 2/2 | 89.1초 | 10.8초 | 612.5 |

마르코 4회는 P 진화, 피오 4회는 H+R 합체로 완주했다. Slug 4회는 실제 탑승 상태로 보스에 진입했다. 보고된 runtime issue는 0. [원본 결과](design/mission-pilot-v012.json).

완성 화력으로 수백 적을 처치하고 보스를 끝내는 규칙은 확인됐다. **재미·캐릭터 간 동등한 난이도·장기 반복성의 증거는 아니다.** 완료가 약 75~124초로 기획의 4~6분보다 짧다. 강제 대기나 보스 HP를 늘려 분량을 맞추지 않았다. 이후 사람의 완주율과 선택·이동 시간을 측정해 지역 구성과 압박을 조정해야 한다.

## 인앱 브라우저 실제 조작

localhost에서 디버그 능력치 주입 없이 버튼·키보드·단일 포인터로 확인했다.

1. 마르코 출격 → 전방 포로와 수용소 경비 제압 → 포로 3명·핵심 1개 → P 3단계와 진화 선택.
2. 37초/137처치에 자발적 귀환 → 처치 27C + 정예·구출·거점 135C + 첫 보고 100C = **262C** 지급.
3. 기지 무기고에서 P 관통 분열 **200C 구매** → 잔액 62C. 새로고침 후 유지.
4. 새 판 P 1단계 다음 성장에서 **P 관통 분열 후보 등장·선택**, 전투 복귀.
5. 두 번째 마르코 판 8C, 피오 구출 판 27C 정산 → 보유 97C.
6. 기초 체력 **80C 구매** → 17C와 훈련 1단계 저장. 새로고침 뒤 피오 출격 최대 HP **105** 확인.
7. 390×844 로비/전투, 320×640 선택/전투 확인. 스틱 단일 포인터 드래그와 키보드 입력, pause/resume 확인.

화면 증거는 `docs/images/v012-*.png`다. 실제 브라우저에서 보스 승리까지의 수동 완주는 아직 검증하지 않았다. 해당 전체 경로는 위 모델 주행으로 검증했다. 실물 휴대전화에서 두 손 멀티터치와 저사양 장시간 성능도 미검증이다.

## 발견 후 수정

- Slug의 F가 보스 진입 대신 하차하던 우선순위 수정.
- 피오가 Slug 주포를 쓸 때 강화 탄창도 유지하도록 수정.
- 합체 후 재료 H/R을 새 총으로 다시 제시하지 않도록 수정.
- 보급의 한 종류 무작위 총 제시로 R을 못 얻던 문제: 빈 슬롯에 두 종류를 모두 제시.
- 거점의 남은 경비 수·보급 준비 표시와 가까운 경비 조준 우선순위 추가.
- 선택/결과 checkpoint 손상으로 UI가 갇히는 상태 거부·복구 정산 추가.
- 선택 필드 누락을 프로필 초기화로 처리하지 않고 기본값 보충. 저장 실패 시 잔액·해금의 메모리 확정 방지.
